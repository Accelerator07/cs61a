python-lab · 第 1 课

让 Python 在 VS Code 里跑起来，并停在第一个断点上

这一课只解决一件事：按下 F5，程序停在你指定的那一行，然后你能看清楚那里每个变量的值。

第 1 步 · 选解释器

VS Code 不会自己猜你想用哪个 Python——它必须被明确告知。这是唯一一个你必须亲手点的动作，也是以后每个新项目都要重复一次的动作。

  1. 用 VS Code 打开 python-lab 文件夹（Ctrl+K 再 Ctrl+O，或菜单「文件 → 打开文件夹」）。
  2. 点右下角状态栏上的 Python 版本号；或者按 Ctrl+Shift+P 输入 Python: Select Interpreter（中文界面显示为「Python: 选择解释器」）。
  3. 选那个路径里带 .venv 的项。
选对了的样子

状态栏显示类似 Python 3.14.6 ('.venv': venv)，并且打开终端时提示符前面带 (.venv)。

选错的样子

终端里 pip install 明明成功了，代码里还是 ModuleNotFoundError。这不是包装错了，是装到了另一个 Python 里。回到这一步重选。

第 2 步 · 先让它在终端里跑一次

调试之前先确认「不调试时它是对的」，否则你分不清是代码错还是配置错。

  1. 按 Ctrl+`（数字 1 左边那个键）打开集成终端。
  2. 输入 python main.py 回车。

末尾应该看到这几行——15 是 fib(5) 真实的调用次数，最后一行的自检说明脚本逻辑是自洽的：

fib(5) = 5
实际调用次数: 15
理论调用次数: 15
自检通过：实际次数 == 公式次数

看到「不是内部或外部命令」或者版本号不对，说明第 1 步没生效；看到乱码，是终端代码页的问题，跟代码无关。

第 3 步 · 让它停住

这是本课的正题。跑通只是「知道结果」，断点才是「知道过程」。

  1. 打开 main.py，在行号左边点一下，出现红点。在 CALLS += 1（第 16 行）和 result = fib(...)（第 24 行）各下一个。
  2. 按 F5。顶部弹出下拉框时选 Python: 当前文件（终端）。
  3. 程序停在红点那一行，那一行还没执行——这是理解调试器最重要的一点。
  4. 看左侧面板：变量里是此刻的 n、depth、CALLS；调用堆栈里是已经压进去的几层 fib。
  5. 按 F11 走进函数，按 F10 跳过一行，按 Shift+F11 退回上一层，按 F5 直接跳到下一个断点。
为什么第 16 行值得停

CALLS += 1 是这个脚本里唯一被修改的全局状态。停在这里，每按一次 F5，你就能看着它 1、2、3 地涨上去——「递归调用了几次」这件事从公式变成了你亲眼见过的东西。

自检

先别翻上面的内容，凭记忆回答。想不起来再展开。

状态栏没有 (.venv)，最可能是哪一步漏了？

第 1 步选解释器。或者当前终端是在选解释器之前就打开的——关掉终端重新开一个（Ctrl+Shift+`），它会按新配置激活环境。

程序停在红点上，此时那一行代码执行了吗？

没有。断点表示「即将执行这一行」。所以如果断点停在 CALLS += 1，此时看到的 CALLS 还是加之前的值。

F10 和 F11 的区别，用一句话说清。

F10 把整个函数调用当成一步走完，F11 钻进函数体内部。想看 fib 里面发生了什么就用 F11，只想往下推进就用 F10。

调试时想看一个没写在代码里的表达式，比如 n * 2，在哪敲？

调试控制台，Ctrl+Shift+Y。也可以加到左侧「监视」面板里，每步自动重算。
